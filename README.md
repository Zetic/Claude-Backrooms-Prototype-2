# Backrooms map prototype

An infinite, deterministic 2-D Backrooms map. Open `index.html` in a browser;
there is no application build step or runtime dependency.

Each territory contains a reusable **architectural pattern**: its rooms,
circulation, procedural interiors, and entrances are planned together. Global
connectivity links the entrances of these pieces. Traversal through rooms and
open floor is invisible navigation data. Dedicated corridors are generated by
patterns that require them and use the surrounding area's floor treatment.

## Controls

| Control | Function |
|---|---|
| Drag / WASD / arrow keys | Pan; Shift increases keyboard speed |
| Wheel / pinch / `+` / `-` | Zoom |
| `M` / Area map | Semantic area view |

| Generation stage | Patterns, abstract connections, room envelopes, actual traversal, shared entrances |
| Debug toggles | Inspect planning data without changing final architecture |
| Hover | Area, shared DNA, pattern, room envelope, infill, and entrance counts |

The URL hash preserves seed, coordinates, zoom and toggles. For example:
`#seed=31337&x=678&y=443&z=7&traversals=1&entrances=1`.

## Generation

1. **Semantic field and manifestations** select architectural vocabulary,
   footprint, scale and structural roles. Backrooms is substrate; configured
   district-role areas create manifestations; Home/Maintenance remain pockets.
2. **Ownership tiling** provides bounded, addressable pieces with exact floor
   coverage. Hotel envelope dimensions no longer force long, thin strips.
3. **Shared entrance contracts** select exact apertures before either interior
   exists. Base connections are retained. Optional connections are omitted only
   when the existing bounded base-connection bypass permits it. Pockets have a
   specified host entrance. Mixed areas use their configured transition walls.
4. **Architectural patterns** jointly arrange circulation and room envelopes.
   Shared DNA coordinates preferred pattern family, orientation, module and
   corridor width. Structural roles bias pattern selection. Wing layouts align
   to suitable entrances and divide deep envelopes into connected smaller wings.
5. **Procedural infill** generates rooms, bathrooms, furniture, columns, pools,
   partitions and other content inside those envelopes. Required entrances are
   constraints on the realization. Geometry that cannot provide access is
   retried within a fixed budget, followed by an explicit safe open realization.
6. **Actual traversal** connects entrances and internal doors through existing
   room floor. Paths detour around permanent solids, water and voids. Furniture,
   columns and decorative partitions preserve the required walking clearance.
7. **Boundary realization** opens the previously specified shared apertures.
   It never searches completed interiors for a replacement doorway.

There is no district corridor network cut through these pieces, route-floor
colouring, subtraction into residual parcels, or arbitrary unserved support
floor. The territory's internal traversal graph connects its actual rooms and
plugs into its neighbors through shared entrances.

## Reusable pattern catalogue

| Pattern | Organization |
|---|---|
| `loop` | Circulation around a central room with procedural infill |
| `elbow` | L passage enclosing a corner room |
| `cross` | Cross junction with four room envelopes |
| `wing` | Shared access serving room banks; deep pieces contain connected wings |
| `enfilade` | A sequence of connected rooms with no separate corridor |
| `open` | Traversal through one open space and its procedural contents |

All patterns are available to multiple semantic areas. Geometry selection uses
profile data and dimensional fit; the planner has no biome-name branches.
An area's `generation` configuration supplies pattern weights, room-frontage
ranges, depth bounds, aspect bounds, and optional infill weights. Its `zones`
configuration supplies the procedural room vocabulary.

For example, the same profile can be used by several area definitions:

```js
generation: {
  patterns: { loop: 2, elbow: 2, cross: 1, wing: 3, enfilade: 2, open: 2 },
  roomFront: [6, 12],
  roomDepth: [4, 16],
  maxRoomAspect: 2.6
}
```

## Modules and APIs

| Module | Responsibility |
|---|---|
| `core.js` | Seeded hashing, PRNG, geometry primitives |
| `areas.js`, `manifestation.js` | Vocabulary, reusable profile data, spatial manifestations, structural roles, shared DNA |
| `layout.js` | Ownership envelopes, adjacency, pocket placement, connection selection rules |
| `structure.js` | Architectural composition metadata and canonical shared entrances |
| `spaceplan.js` | Pattern selection, coordinated room/circulation groups, internal interfaces |
| `zones.js` | Procedural room infill |
| `traversal.js` | Bounded floor traversal, obstacle avoidance, entrance/detail clearance |
| `interior.js` | Infill realization, actual room links, final geometry |
| `boundary.js` | Exact shared-entrance realization |
| `world.js` | Lazy generation, bounded caches, spatial queries and inspection |
| `render.js` | Canvas presentation, LOD/tile caching, debug-only route overlays |

Useful APIs:

```js
const W = new BR.World(31337);
const T = BR.territoryAt(W, 678, 443);
W.pattern(T);                       // patterns, room envelopes, interfaces, ports
W.interior(T);                      // geometry, actual rooms, links, traversal paths
BR.connectionPorts(W, T, neighbor); // shared apertures; no interior dependency
W.connectionsIn(x0, y0, x1, y1);   // connections of pieces intersecting the query
W.collect(x0, y0, x1, y1, Infinity, { interiors: true });
W.inspect(x, y);
```

Every result derives from the seed and stable spatial identity. Caches can be
evicted and rebuilt; query order cannot determine architecture. Ownership uses
integer metres; interior dimensions and apertures may use fractional metres.

## Verification

```sh
node tests/run-all.js
```

The runner checks five seeds: `31337`, `7`, `12345`, `99`, and `4242`. Checks cover:

- Complete geometry under reversed requests, unrelated visits, tiled queries,
  aggressive cache eviction, and far negative coordinates.
- Exact territory tiling and exact nonoverlapping architectural floor coverage.
- All six patterns in multiple semantic profiles and their defining arrangements.
- Matching shared entrances, full-aperture access, and exact wall gaps.
- Global room reachability and local traversal connectivity.
- Exact path coverage by room floor and 0.6 m player clearance against walls,
  pools, permanent solids, furniture and columns.
- Physically disconnected infill rejection and explicit complexity failure.
- Reuse of a room archetype under another semantic profile.
- HTML controller initialization, debugger presets/toggles, inspection, seed,
  coordinate navigation, zoom, and shared URL state.

GitHub Actions runs the same checks on pull requests and `main` pushes.
The controller harness is not a browser-engine test.

Optional render review tooling uses `@napi-rs/canvas`:

```sh
node scripts/render-review.js
```

It captures the production renderer, records reproducible coordinates, and
checks that enabling/disabling debug overlays leaves final pixels unchanged.

## Current bounds

Patterns contain at most 96 architectural blocks. Infill has four attempts
before an explicit safe realization. Each room's floor search has a 384-rectangle
cap. Ownership, pattern, infill, and boundary caches have configurable limits.

Architecture remains axis-aligned and its outer ownership envelopes remain
rectilinear. The current catalogue has six patterns; richer profiles and nested
architectural compositions can extend it. Rounded-room infill is not supported
by the current rectilinear traversal solver and is rejected during selection.
Vertical circulation remains decorative. Generated coordinates change from the
previous circulation implementation; determinism applies within this generator
version. The old `sites.js`, `cluster.js`, and `corridors.js` remain unused v1 code.
